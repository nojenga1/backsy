How it's built.

Backsy is deliberately small. The whole prototype is one Python file on the standard library plus SQLite — no framework, no package manager, nothing to install.

The whole stack

  • http.server for routing and static delivery
  • sqlite3 for accounts and transfers
  • secrets for claim tokens
  • One HTML page, no build step, no bundler

Run it with python app.py. There is no dependency file because there are no dependencies.

Data model

Two tables. accounts holds a name and a balance. transfers holds a token, sender, recipient, amount, status, and the two timestamps that define the hold window. A transfer's status is one of pending, claimed, cancelled, expired.

The reversible mechanism

Sending debits the sender inside BEGIN IMMEDIATE with a conditional update, so an insufficient balance matches zero rows and the whole send rolls back. Settling a transfer updates it only while it is still pending; the second of two racing claims matches nothing and pays out nothing. That single WHERE status='pending' is the entire concurrency story.

Expiry without a scheduler

Overdue transfers are swept at the start of each request rather than by a cron job. At prototype volume the scan is free, and it removes a moving part. It is marked in the source as the first thing to replace if transfer volume grows.

API

  • GET /api/state?user= — balance, in-flight total, sent and incoming lists
  • POST /api/send — {user, to, amount}, returns a claim token
  • POST /api/claim — {user, token}
  • POST /api/cancel — {user, token}, sender only
  • GET /c/<token> — the claim page

Tests

python app.py --test runs a self-check covering double claims, cancel-after-claim, cancellation by a non-sender, overdraft, expiry, and a closing invariant that the total of every balance plus everything in escrow never changes.

What is real, and what isn't

Real: the program on devnet, the escrow accounts it holds funds in, the claim links, the expiry. Not real: the money, which is devnet test currency. The demo wallet at /app still runs the original SQLite simulation; the on-chain one lives at /wallet.

Backsy runs on Solana devnet, a test network. The program is deployed and transfers really happen on-chain, but devnet coins have no value and the program has not been audited. Do not treat it as a place for real money.
